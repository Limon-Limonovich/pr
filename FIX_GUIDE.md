# Инструкция по исправлению дефектов «Практической работы №5»

Инструкция относится к дефектам из [`BUG_REPORT.md`](BUG_REPORT.md). Рекомендуется выполнять шаги в указанном порядке, а архив создавать заново только после успешной проверки.

## 1. Подготовить рабочую копию

1. Распаковать `Практическая работа №5.7z` в отдельную папку.
2. Закрыть Word и Visual Studio, чтобы они не создавали lock-файлы и не удерживали `.vs`/`bin`/`obj`.
3. Сохранить исходный архив как резервную копию.
4. Все изменения вносить в распакованную копию, а не пытаться редактировать файлы внутри 7z.

---

## 2. Исправить solution-файл и версию среды (SLN-001, ENV-001)

### 2.1 Удалить пустую первую строку

Открыть `ПР5/DeliveryCalculator.sln` в редакторе, отображающем пустые строки. Файл должен начинаться **сразу** с:

```text
Microsoft Visual Studio Solution File, Format Version 12.00
```

Допустим UTF-8 BOM, но между BOM и буквой `M` не должно быть `CRLF`.

Проверка PowerShell:

```powershell
$solution = '.\ПР5\DeliveryCalculator.sln'
$firstLine = Get-Content -LiteralPath $solution -Encoding UTF8 -TotalCount 1
if ($firstLine -ne 'Microsoft Visual Studio Solution File, Format Version 12.00') {
    throw "Некорректная первая строка solution: '$firstLine'"
}
```

### 2.2 Привести solution к Visual Studio 2022

Поскольку методичка требует Visual Studio 2022, рекомендуемый заголовок имеет major version 17:

```text
Microsoft Visual Studio Solution File, Format Version 12.00
# Visual Studio Version 17
VisualStudioVersion = <полная числовая версия установленной VS 2022>
MinimumVisualStudioVersion = 10.0.40219.1
```

Не оставлять суффикс `stable` в `VisualStudioVersion`.

Наиболее надёжный способ:

1. Запустить Visual Studio 2022.
2. Открыть исправленный `.sln`.
3. Если IDE предложит обновить/пересохранить решение — согласиться.
4. Проверить, что `DeliveryCalculator/DeliveryCalculator.csproj` загружен, а три `.cs` видны в Solution Explorer.
5. Закрыть и повторно открыть solution.

Если VS2022 не принимает существующий `.sln`:

1. сохранить старый файл под другим именем;
2. создать в папке `ПР5` пустое решение `DeliveryCalculator` в VS2022;
3. выбрать **Add → Existing Project**;
4. добавить `DeliveryCalculator/DeliveryCalculator.csproj`;
5. проверить конфигурацию `Debug | x86`;
6. удалить резервный некорректный `.sln` из итоговой поставки.

### 2.3 Проверить сборку

В Developer Command Prompt for VS 2022:

```bat
msbuild DeliveryCalculator.sln /t:Rebuild /p:Configuration=Debug /p:Platform=x86
```

Ожидается `Build succeeded`, без ошибок разбора solution.

## 3. Добавить проверку точности массы (LOGIC-001)

В `DeliveryCalculator/TariffService.cs` добавить проверку после проверки диапазона массы. Вариант, совместимый с указанным в проекте C# 5:

```csharp
public static decimal Calculate(
    decimal weight, int distance, bool express)
{
    if (weight <= 0 || weight > 30)
        throw new ArgumentException(
            "Масса должна быть больше 0 и не больше 30 кг.");

    if (decimal.Round(weight, 2) != weight)
        throw new ArgumentException(
            "Масса должна содержать не более 2 знаков после запятой.");

    if (distance < 1 || distance > 1000)
        throw new ArgumentException(
            "Расстояние должно быть от 1 до 1000 км.");

    decimal cost = 200m + 40m * weight + 5m * distance;
    if (express) cost *= 1.5m;
    return Math.Round(cost, 2, MidpointRounding.AwayFromZero);
}
```

Почему проверка выполняется в сервисе:

- `NumericUpDown.DecimalPlaces = 2` защищает только текущую форму;
- `TariffService` объявлен повторно используемым вычислительным модулем;
- вызывающий код не должен иметь возможность обойти обязательное ограничение.

Если ограничение точности по замыслу относится **только к UI**, вместо изменения кода нужно явно зафиксировать это в требованиях. Не следует оставлять неоднозначность между методичкой и контрактом сервиса.

### Обязательные модульные проверки

| Вызов | Ожидается |
|---|---|
| `Calculate(0.01m, 1, false)` | `205.40m` |
| `Calculate(2m, 10, false)` | `330.00m` |
| `Calculate(2.10m, 10, false)` | допустимое значение |
| `Calculate(30m, 1000, true)` | `9600.00m` |
| `Calculate(2.001m, 10, false)` | `ArgumentException` о точности массы |
| `Calculate(0m, 10, false)` | `ArgumentException` о диапазоне массы |
| `Calculate(2m, 0, false)` | `ArgumentException` о диапазоне расстояния |

Рекомендуется создать отдельный MSTest-проект .NET Framework 4.8 и добавить ссылку на `DeliveryCalculator`. Минимальный набор автоматических тестов должен покрывать обычный расчёт, срочность, обе допустимые границы и четыре недопустимые границы, а также массу с тремя десятичными знаками.

## 4. Полностью сбрасывать состояние результата (UI-001)

В `MainForm.cs` заменить `ClearResult` на:

```csharp
private void ClearResult(object sender, EventArgs e)
{
    result.ForeColor = SystemColors.ControlText;
    result.Text = "Параметры изменены. Нажмите Рассчитать";
}
```

`SystemColors` уже доступен через `using System.Drawing;`.

Проверить два сценария:

1. ошибка (красный текст) → изменение поля → нейтральный системный цвет;
2. успешный расчёт (зелёный текст) → изменение поля → нейтральный системный цвет.

В обоих случаях старая сумма или причина ошибки не должна оставаться на форме.

## 5. Исправить методичку (DOC-001, DOC-002, DOC-003)

### 5.1 Заполнить таблицу контрольных испытаний

В раздел 5 внести следующие значения:

| Тест | Масса и расстояние | Срочно | Ожидается |
|---|---|:---:|---|
| T1 | 2 кг; 10 км | Нет | `Стоимость: 330,00 руб.` |
| T2 | 2 кг; 10 км | Да | `Стоимость: 495,00 руб.` |
| T3a | 0,01 кг; 1 км | Нет | `Стоимость: 205,40 руб.` |
| T3b | 30 кг; 1000 км | Нет | `Стоимость: 6400,00 руб.` |
| T4 | 0 кг; 10 км | Нет | сообщение о допустимой массе |
| T5 | 30,01 кг; 10 км | Нет | сообщение о допустимой массе |
| T6 | 2 кг; 0 км | Нет | сообщение о допустимом расстоянии |
| T7 | 2 кг; 1001 км | Нет | сообщение о допустимом расстоянии |
| T8 | выполнить T1, затем изменить массу с 2 на 3 и не нажимать кнопку; расстояние оставить 10 км | Нет | старая стоимость скрыта; нейтральная подсказка о повторном расчёте |

Для LOGIC-001 добавить отдельный модульный тест, например **T9**:

| Тест | Вход | Ожидается |
|---|---|---|
| T9 | прямой вызов `Calculate(2.001m, 10, false)` | отказ: не более 2 знаков после запятой |

T9 нельзя корректно выполнить через текущий `NumericUpDown`, поэтому в документе нужно явно пометить его как тест `TariffService`, а не формы.

### 5.2 Исправить ссылки в матрице требований

Рекомендуемые ссылки:

| Требование | Тесты |
|---|---|
| Масса в диапазоне и до двух знаков | T3a, T3b, T4, T5, T9 |
| Расстояние 1–1000, целое | T3a, T3b, T6, T7 |
| Формула | T1, T3a, T3b |
| Срочность | T2 |
| Два знака в результате | T1, T2, T3a, T3b |
| Понятная ошибка и продолжение работы | T4–T7 + восстановление после T4 |
| Скрытие прежнего результата | T8 |

Не использовать одиночный ID `T3`, которого нет в таблице.

### 5.3 Удалить или заполнить пустой столбец

В первой таблице:

- либо удалить пустой левый столбец через **Макет таблицы → Удалить → Удалить столбцы**;
- либо назвать его `ID` и заполнить значениями `R1`–`R7`.

Второй вариант удобнее для трассировки требований в отчёте.

### 5.4 Обновить фрагмент кода в документе

После исправления `TariffService.cs` заменить пример кода в разделе 3, чтобы методичка и прилагаемый проект не расходились. Также добавить пояснение проверки точности и T9.

### 5.5 Проверить документ перед сохранением

1. Обновить оглавление и поля, если они есть.
2. Проверить, что таблицы не разъехались по страницам.
3. Выполнить поиск `T3` и исправить неоднозначные ссылки.
4. Выполнить поиск старого фрагмента `TariffService` без проверки точности.
5. Сохранить DOCX.
6. Полностью закрыть Word до упаковки.

## 6. Очистить поставку от локальных и генерируемых файлов (PKG-001)

### 6.1 Удалить ненужные файлы

Из корня распакованной работы удалить:

```powershell
$root = '.\Практическая работа №5'

Remove-Item -LiteralPath "$root\~`$актическая работа 5.docx" `
    -Force -ErrorAction SilentlyContinue
Remove-Item -LiteralPath "$root\ПР5\.vs" `
    -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item -LiteralPath "$root\ПР5\DeliveryCalculator\bin" `
    -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item -LiteralPath "$root\ПР5\DeliveryCalculator\obj" `
    -Recurse -Force -ErrorAction SilentlyContinue
```

Сначала закройте Word и Visual Studio. Не удаляйте `.sln`, `.csproj` и исходные `.cs`.

### 6.2 Очистить свойства документа

В Word:

1. **Файл → Сведения → Поиск проблем → Инспектор документов**.
2. Проверить «Свойства документа и персональные данные».
3. Удалить персональные свойства, если имя автора не является обязательной частью поставки.
4. Повторно запустить инспектор и убедиться, что нежелательных данных нет.

### 6.3 Добавить правила игнорирования при ведении проекта в Git

Рекомендуемый `.gitignore`:

```gitignore
.vs/
[Bb]in/
[Oo]bj/
*.suo
*.user
~$*
```

### 6.4 Не смешивать исходники и готовый бинарник

Если преподавателю/пользователю нужен запускаемый файл:

- собрать **Release** из уже исправленных исходников;
- разместить его в отдельном архиве/артефакте;
- не прикладывать `obj`, `.vs`, cache-файлы и PDB, если отладочные символы не запрошены;
- указать SHA-256 и версию исходников, из которых создан EXE.

## 7. Выполнить итоговую проверку

### 7.1 Пересборка

1. Удалить `bin` и `obj`.
2. Открыть solution в Visual Studio 2022.
3. Выполнить **Build → Rebuild Solution**.
4. Закрыть приложение и IDE.
5. Повторно открыть solution и выполнить T1.

### 7.2 Регрессионная матрица

Выполнить T1–T9 и дополнительный сценарий из задания:

- 30 кг, 1000 км, срочно → `9600,00 руб.`;
- после T4 исправить массу на 2 и пересчитать → `330,00 руб.`;
- после ошибки/успеха изменить любой параметр → нейтральное сообщение без старого цвета;
- для версии v2 отдельно проверить 380,00; 570,00; 255,40; 6450,00.

Не смешивать результаты исходной версии и v2 в одной таблице.

### 7.3 Контроль чистоты папки

Перед упаковкой ожидаются только:

```text
Практическая работа №5/
├── Практическая работа 5.docx
└── ПР5/
    ├── DeliveryCalculator.sln
    └── DeliveryCalculator/
        ├── DeliveryCalculator.csproj
        ├── MainForm.cs
        ├── Program.cs
        └── TariffService.cs
```

Проверка PowerShell на запрещённые элементы:

```powershell
$bad = Get-ChildItem '.\Практическая работа №5' -Recurse -Force |
    Where-Object {
        $_.Name -like '~$*' -or
        $_.Name -in '.vs', 'bin', 'obj' -or
        $_.Extension -in '.suo', '.pdb'
    }

if ($bad) {
    $bad | Select-Object FullName
    throw 'В поставке остались временные или генерируемые файлы.'
}
```

### 7.4 Создать новый архив

1. Убедиться, что Word и Visual Studio закрыты.
2. Упаковать папку `Практическая работа №5` в новый 7z/ZIP.
3. Распаковать новый архив в другую пустую папку.
4. Проверить дерево файлов, первую строку `.sln`, открытие DOCX и сборку solution.
5. Только после этого заменить исходный архив.

## 8. Definition of Done

Исправление можно считать завершённым, когда одновременно выполнены все условия:

- `.sln` начинается с корректного заголовка и собирается в VS2022/MSBuild;
- версия среды в задании и solution совпадает;
- T1–T8 полностью определены, ссылки T3a/T3b согласованы;
- `TariffService` не принимает более двух значащих десятичных знаков;
- после изменения параметров сбрасываются и текст, и цвет результата;
- T1–T9 и проверки v2 пройдены;
- в архиве нет `~$*`, `.vs`, `bin`, `obj`, `.suo`, PDB и локальных абсолютных путей;
- новый архив повторно распакован и проверен с нуля.
